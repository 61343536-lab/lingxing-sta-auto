# 领星待发货单明细查询设计

## 决策问题

第一阶段已经从本月已完成装箱任务中提取候选 SP。第二阶段需要确认这些 SP
是否仍处于发货单“待发货”状态，并取得后续创建货件所需的完整商品明细。

本阶段只读取数据，不创建货件、不发货、不修改库存。

## 关键对象

- 候选 SP：第一阶段输出的发货单号。
- 待发货单：状态为 `0`、未删除、创建时间位于最近三个月的发货单。
- 发货单详情：点击页面蓝色 SP 发货单号后展示的订单和商品明细。
- 已有关系：FBA 货件号、STA 货件 ID 或 STA 任务编号。

## 接口映射

- 列表：
  `POST /erp/sc/routing/storage/shipment/getInboundShipmentList`
- 批量详情：
  `POST /erp/sc/routing/storage/shipment/getInboundShipmentListMwsDetailList`

列表使用 `senior_search_list` 对 `shipment_sn` 做精确批量搜索，固定查询
`status=0`、`time_type=3`、`is_delete=0`。详情接口每批最多查询 50 个 SP。

## 判断规则

- 状态不再是待发货：排除。
- 已有 FBA 货件号：排除，避免重复创建。
- 已有 STA 关系但尚无 FBA 货件号：进入待核验，不直接重复创建。
- 关系字段、店铺归属或商品明细缺损：进入待核验。
- 待发货、未删除、店铺范围明确且未发现已有货件或 STA：候选。

这里的“候选”只表示可以进入后续建单准备，不代表本阶段授权写入。

## MCP 工具

1. `get_recent_three_month_range`
   - 按业务时区读取当天。
   - 开始日期为当天向前减三个自然月，同日不存在时取目标月最后一天。
2. `list_pending_shipments`
   - 每次查询一页。
   - 输入最多 50 个 SP，固定使用待发货、创建时间和未删除条件。
   - 返回归一化发货单摘要、分页信息和筛选原因。
3. `get_pending_shipment_details`
   - 输入最多 50 个 SP。
   - 调用批量详情接口，返回发货单及其全部商品明细。
   - 报告未返回 SP、范围外记录和候选分类。

## 验证

- 日期覆盖月末和闰年回退。
- 请求体严格包含待发货、最近三个月、未删除和精确 SP 搜索条件。
- 批量详情上限为 50。
- 店铺范围、已有 FBA/STA、状态变化和字段缺损均有测试。
- 客户端仍只允许明确列出的只读接口，未知或写接口继续拒绝。
